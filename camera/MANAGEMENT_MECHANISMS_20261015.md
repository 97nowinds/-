# 飞书群通知机制与精简记录

日期：2026-10-15。当前采用后台直接通知指定飞书群，日常接收人员无需注册网站账号。

火焰报警后续已补充视觉与硬件联合结果接入，覆盖区域尚待现场确认；详见 [火焰联合接入](FIRE_FUSION_20261015.md)。下文硬件链路仍保留，视觉路径同样采用严格快照、权威时间及三群通知。

## 已移除

- 个人账号模块、创建/停用/重置接口、令牌哈希库的读写逻辑。
- 网页个人账号表单、人员角色授权及重新启用个人账号的开关。
- 配置中的实验人员、负责人、观察员网页令牌模板；不再按实际人员分配网站权限。
- 旧点对点接入脚本、手机号/邮箱查询、私聊消息及电话加急接口。
- 通知队列中的应用私聊 transport 分支；现在只接受群 Webhook。

不删除现存人员识别库、录像、证据、历史事件数据库或加密凭据。旧数据库中如有历史账号表，不再读取，也不会据此恢复账号；新数据库不会创建它。

## 保留的必要链路

队友检测结果／本地火焰传感器 → 校验真实观测及证据 → 分级规则 → 持久化队列 → 指定飞书群。

| 事件 | 处理 |
| --- | --- |
| 人员进入、正常仪器交互 | L0 留档，不通知 |
| 确认防护违规 | L1，实验人员群，附原始对应帧的标注快照 |
| 持续有效违规达到 60 秒 | L2，实验人员群及实验负责人群 |
| 火焰传感器告警 | L3，实验人员、负责人、实验室管理员三个群 |

防护默认要求至少 3 个不同源帧、持续至少 5 秒，观测间隔超过 15 秒重计。unknown、低置信度或不可见打断累计，不代表已整改。口罩规则开启；实验服、手套保留结果契约，等待实际检测联调后再开启。

人员接收范围由飞书群成员决定。后台只保留维护管理员和检测服务两类技术鉴权；它们不是要求实验人员注册的账号。维护令牌用于查询事件、查看证据、编辑规则和路由，producer Token 只能提交指定实验室/相机的证据。普通群成员不用打开管理页。

## 证据与时间

按 camera_id + snapshot_id + track_id 找发送时的真实身份，不相信回传姓名或数组顺序。独立发送进程与前端共享 DPAPI 加密的不可变快照索引，图片校验摘要、尺寸及人员框。未知身份、旧框、缺图、未确认时间域不发实名告警，不能退化成伪造文字证据。

源时钟标记来自 camera.timing.event_time_domain。生产配置要求 authority，不能以发送时间冒充采集时间，也不能因接收端填写 authority 就接纳源时钟数据。独立发送端仍为 source 时应继续拦截，等待真实时钟转换联调。

## 告警与发送

火焰只信任本地串口的新鲜状态，独立轮询不等待远端模型请求。恢复信号、断线和温湿度心跳严格区分；断线不清除告警。维护人员可认领，恢复后填写现场核查记录关闭。最新状态轮询不能保证捕获小于 0.25 秒的脉冲，硬件需保持告警或另做事件队列。

群发送保留去重、三线程投递、事务领取及租约、发送前路由复查、失败重试和安全日志。普通消息有 TTL，L3 持续重试。Webhook 超时后重试仍可能重复，不能宣称外部恰好一次。恢复后取消未开始投递的旧火焰告警，已开始的网络请求不可撤回。

## 配置和维护

- config/management.json：三个群的环境变量路由、事件规则及技术鉴权。
- scripts/configure_feishu_evidence.py：三个群机器人和应用图片上传配置，本机隐藏输入；明确点击后向三群发送合成图文连接测试。
- scripts/configure_feishu_group.py：保留单群机器人连接工具。
- feishu_app.py：仅保留图片上传所需应用 Token，以及本机 DPAPI 凭据保存能力。
- /management：可选后台维护页面，没有注册入口或个人角色授权。
- /api/management/evidence：保留 producer Bearer Token、相机范围、快照和时间校验。

三个群配置工具与默认配置使用同一份路由，防止重新配置时丢失 L2 升级或火焰三群路由。数据库内既有自定义路由仍优先，不能只看配置文件就认定运行时已生效。
