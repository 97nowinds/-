# 实验室人员—仪器交互模块：接口与使用说明

## 给接入方 AI 的快速摘要

- 公共 Python 包：`模块/lab_instrument_interaction`
- 唯一推荐入口：`InstrumentInteractionModule`
- 当前接口版本：`1.1`
- 当前插件版本：`0.2.0`
- 主方法：`analyze_video(video_path, camera_id, identity_timeline, output_dir=None)`
- 实时入口：`create_stream(...)`，随后持续调用 `stream.process_frame(...)`
- 输入：视频文件、摄像头编号、可选的逐时刻人员身份与人员框。
- 输出：包含“哪个人、哪台仪器、什么时间发生交互”的 Python 字典，同时生成 `result.json` 和标注视频。
- 模型必须在应用启动时加载一次并复用；不要每次调用都重新创建模块对象。
- 不要直接导入 `v4`、`v5` 或调用其中的私有函数。
- 外部人员身份只用于给交互事件关联姓名，不参与交互真假判定。
- `process_frame()` 是非阻塞投递接口，MiniCPM在后台线程分析最近2秒画面。
- 每个摄像头建立一个长期复用的流式会话，不能每帧重新创建模块或会话。
- 24小时监控正式接入应优先使用流式接口；`analyze_video()` 主要用于离线录像和回归测试。
- 本模块不保存24小时录像；录像、断线重连、数据库和网页显示由接入方负责。

### 给接入方 AI 的硬性约束

1. 只允许从 `lab_instrument_interaction` 导入公共类，不要把 `v4`、`v5` 内部实现复制进对方项目。
2. 整个应用只创建一个 `InstrumentInteractionModule`；每个摄像头只创建一个长期会话。
3. 每一帧都调用 `process_frame()`，并传入队友本帧的人员结果；无人时传 `[]`，缺少外部结果时才传 `None`。
4. `process_frame()` 返回的是后台最新已确认状态，不是当前帧同步推理结果；不得因为一次返回为空就擅自结束历史事件。
5. 必须消费并持久化 `events`，保存 `last_event_sequence` 游标，同时监控 `error`、`event_gap_detected`、`analysis_lag_seconds` 和 `dropped_frames`。
6. 接入和升级不得改动仪器标定、提示词、融合阈值及内部模型调用；这些属于插件内部实现。

## 一、模块做什么

模块针对固定监控摄像头和预先标定的固定仪器，判断人员是否与仪器发生实际交互。

当前后端由两部分组成：

1. MiniCPM-V 4.6 查看短时间连续画面，判断是否出现触摸、按动、开关盖子等交互。
2. YOLO-Pose 与固定仪器区域形成手腕/手臂时序关系，只在证据很强时补充 MiniCPM 漏检。

人员身份由接入方提供。本模块使用人员框把外部身份与内部交互轨迹关联，最后输出人员姓名和仪器名称。

## 四、输入接口

### 4.1 `video_path`

- 类型：`str | pathlib.Path`
- 含义：需要分析的视频文件。
- 视频必须来自 `camera_id` 指定的固定摄像头。

### 4.2 `camera_id`

- 类型：`str`
- 当前可选值：`lab_camera_view_1`、`lab_camera_view_2`。
- 不能省略真实摄像头编号后随意使用默认值，否则仪器区域会对应错误。

可以查询当前摄像头和仪器：

```python
print(InstrumentInteractionModule.supported_cameras())
```

### 4.3 `identity_timeline`

- 类型：Python 列表、包含 `frames` 的字典，或 JSON 文件路径。
- 可以传 `None`。传 `None` 时仍然判断交互，但只返回内部临时编号，例如 `person_01`。
- 建议接入方把每次人员识别/跟踪结果都加入时间线。

标准格式：

```python
person_results = [
    {
        "timestamp": 0.0,
        "persons": [
            {
                "person_id": "employee_001",
                "person_name": "张三",
                "bbox": [281, 1, 407, 428],
                "confidence": 0.96,
            }
        ],
    },
    {
        "timestamp": 0.2,
        "persons": [
            {
                "person_id": "employee_001",
                "person_name": "张三",
                "bbox": [280, 1, 418, 428],
                "confidence": 0.97,
            }
        ],
    },
]
```

字段约定：

| 字段 | 必需 | 类型 | 说明 |
|---|---:|---|---|
| `timestamp` | 是 | `float` | 相对于视频开头的秒数，从 `0.0` 开始 |
| `persons` | 是 | `list` | 该时刻画面里识别到的所有人 |
| `person_id` | 是 | `str` | 接入方跟踪系统提供的稳定编号；同一个人跨帧必须保持一致 |
| `person_name` | 否 | `str` | 人脸识别得到的姓名；未知时可为 `None` |
| `bbox` | 是 | 四个数字 | 原视频像素坐标 `[x1, y1, x2, y2]` |
| `confidence` | 否 | `float` | 接入方人员识别置信度，仅用于记录 |

重要限制：

- `bbox` 必须对应传入视频的原始画面，不能是网页缩放后的坐标。
- 不能只提供姓名而不提供人员框，否则多人员场景无法确定是谁在操作。
- 同一个时间戳内不能出现重复的 `person_id`。
- `person_id` 应来自跟踪结果，而不是每一帧重新随机生成。
- 默认允许外部时间戳与内部采样时间相差最多 `0.5` 秒，因此建议至少每秒提供 2～5 次人员框。

也兼容以下字段别名：`timestamp_seconds`、`people`、`track_id`、`name`。

### 4.4 `output_dir`

- 类型：`str | pathlib.Path | None`
- 指定该次分析的输出目录。
- 传 `None` 时自动输出到 `模块/outputs/minicpm_v46_vrm_hybrid/`。
- 接入方应保证不同任务使用不同的输出目录，不要让两个任务同时写同一个目录。

## 五、输出接口

`analyze_video()` 返回普通 Python 字典。核心结构如下：

```json
{
  "interface_version": "1.1",
  "plugin_version": "0.2.0",
  "camera_id": "lab_camera_view_2",
  "interactions": [
    {
      "interaction_id": "hybrid_interaction_0001",
      "person_id": "employee_001",
      "person_name": "张三",
      "internal_person_id": "person_01",
      "instrument_id": "instrument_006",
      "instrument_name": "高速离心机",
      "is_interacting": true,
      "state": "interaction_interval",
      "start_time": 2.0,
      "end_time": 8.0,
      "duration_seconds": 6.0,
      "confidence": 0.91,
      "identity_source": "external_person_recognition",
      "decision_sources": ["minicpm_v46_positive"]
    }
  ],
  "summary": {
    "is_interacting_video": true,
    "interaction_count": 1,
    "person_ids": ["employee_001"],
    "person_names": ["张三"]
  },
  "artifacts": {
    "annotated_video": ".../annotated.mp4",
    "result_json": ".../result.json"
  }
}
```

说明：

- `interactions` 只保存已经成立的交互时间段；列表为空表示该视频没有确认交互。
- 每个事件的 `is_interacting` 固定为 `true`。
- `state="interaction_interval"` 表示这是一个分析完成后的交互区间，不是逐帧实时状态。
- `internal_person_id` 是本模块的内部轨迹编号，主要用于排错。
- `identity_source="external_person_recognition"` 表示已经匹配到接入方身份。
- `identity_source="internal_tracker"` 表示没有匹配到外部身份，此时不要把 `person_01` 当成真实姓名。
- `decision_sources` 用于说明结果来自 MiniCPM、强 VRM 证据或两者共同支持。

结果还会写入 `result.json`。接入方可以直接使用返回字典，不需要再次读取这个文件。

## 六、模型生命周期和并发

正确方式：

```python
module = InstrumentInteractionModule(preload_models=True)
for video in videos:
    result = module.analyze_video(video, camera_id="lab_camera_view_2")
module.close()
```

错误方式：

```python
for video in videos:
    module = InstrumentInteractionModule(preload_models=True)  # 会反复加载模型
```

同一个模块对象的 `analyze_video()` 已加串行锁，不允许多个线程同时调用同一份 MiniCPM。接入方可以把任务放入自己的队列，依次交给这个对象。

## 七、24小时实时 `process_frame()` 接口

完整示例：`模块/examples/realtime_stream_example.py`。

### 7.1 创建长期会话

应用启动时加载一次模型，每个摄像头创建一个会话：

```python
module = InstrumentInteractionModule(preload_models=True)

stream = module.create_stream(
    camera_id="lab_camera_view_2",
    frame_size=(768, 432),
)
```

`frame_size` 的顺序是 `(宽, 高)`，必须等于摄像头实际输出尺寸。也可以不传，让模块使用第一帧尺寸初始化。

### 7.2 每帧调用

```python
response = stream.process_frame(
    frame,
    timestamp=timestamp,
    persons=persons,
    after_event_sequence=event_cursor,
)
event_cursor = response["last_event_sequence"]
```

参数：

| 参数 | 必需 | 说明 |
|---|---:|---|
| `frame` | 是 | OpenCV读取的BGR三通道 `numpy.ndarray` |
| `timestamp` | 是 | 会话开始后的秒数；同一会话必须严格递增 |
| `persons` | 是 | 队友在当前帧得到的人员列表 |
| `after_event_sequence` | 建议 | 上一次保存的事件游标，防止漏收或重复处理事件 |

实时 `persons` 格式：

```python
persons = [
    {
        "person_id": "employee_001",
        "person_name": "张三",
        "bbox": [281, 1, 407, 428],
        "confidence": 0.96,
    }
]
```

特别注意：

- `persons=[]` 表示队友已经分析当前帧，确认画面里没有人。
- `persons=None` 表示队友本帧没有提供结果，模块会启用自己的人员检测兜底。
- 正式接入建议每帧都传列表，包括无人时的空列表。
- `process_frame()` 只负责把帧复制进有界队列并返回最新结果，不会等待MiniCPM完成。
- 返回结果通常对应前面约2秒的画面，不是对当前这一帧的瞬时答案。
- 同一流式会话建议只由一个摄像头读取线程按顺序投递，不能并发乱序调用。
- 模块会复制传入帧；`accepted_frame=true` 只表示帧已进入队列，不表示该帧已经完成分析。

### 7.3 返回结构

```json
{
  "stream_schema_version": "1.0",
  "session_id": "stream_ab12cd34ef56",
  "camera_id": "lab_camera_view_2",
  "accepted_frame": true,
  "timestamp": 12.4,
  "status": "running",
  "analysis_pending": true,
  "analysis_lag_seconds": 0.32,
  "current_interactions": [
    {
      "person_id": "employee_001",
      "person_name": "张三",
      "instrument_id": "instrument_006",
      "instrument_name": "高速离心机",
      "is_interacting": true,
      "state": "ongoing",
      "start_time": 8.2,
      "confidence": 0.91,
      "decision_sources": ["minicpm_v46_positive"]
    }
  ],
  "events": [],
  "last_event_sequence": 17,
  "oldest_available_event_sequence": 1,
  "event_gap_detected": false,
  "error": null,
  "metrics": {
    "received_frames": 310,
    "dropped_frames": 0,
    "pose_samples": 62,
    "vlm_calls": 5,
    "queued_frames": 4
  }
}
```

字段用途：

- `current_interactions`：前端当前应该显示的人员—仪器交互状态。
- `events`：本次游标之后新增的开始、结束或错误事件，适合写数据库和推送。
- `accepted_frame`：当前调用是否接收了输入帧；`poll()` 返回 `null`，后台错误时可能为 `false`。
- `status`：`warming_up`、`analyzing`、`running`、`error` 或 `closed`。
- `analysis_lag_seconds`：后台已处理时间与最新输入时间的差值。
- `dropped_frames`：队列满时为保持实时性而丢弃的旧输入帧数；持续增加说明机器带不动。
- `error`：后台错误。非空时必须报警，不能解释为“无交互”。
- `event_gap_detected`：为 `true` 表示接入方游标落后太多，部分旧事件已从内存移除；应报警并检查事件消费程序。

### 7.4 事件格式

开始事件：

```json
{
  "event_sequence": 1,
  "type": "interaction_started",
  "state": "started",
  "is_interacting": true,
  "person_id": "employee_001",
  "person_name": "张三",
  "instrument_id": "instrument_006",
  "instrument_name": "高速离心机",
  "start_time": 8.2,
  "timestamp": 10.8,
  "confidence": 0.91,
  "decision_sources": ["minicpm_v46_positive"]
}
```

结束事件的 `type` 为 `interaction_ended`，`is_interacting` 为 `false`，并增加 `end_time` 和 `duration_seconds`。

事件游标使用规则：

```python
event_cursor = 0

while running:
    response = stream.process_frame(
        frame,
        timestamp=timestamp,
        persons=persons,
        after_event_sequence=event_cursor,
    )
    for event in response["events"]:
        save_event(event)
    event_cursor = response["last_event_sequence"]
```

如果暂时没有新帧，也可调用：

```python
response = stream.poll(after_event_sequence=event_cursor)
```

接入方应先成功保存本次 `events`，再持久化新的 `last_event_sequence`。如果程序崩溃后重新创建了流会话，内存事件历史不会自动恢复；数据库去重和重启后的业务衔接由接入方负责。

### 7.5 关闭、断线和重连

正常退出顺序：

```python
stream.close()
module.close()
```

- 摄像头短暂断线时不要持续伪造空白帧或 `persons=[]`，应暂停投递并执行摄像头重连。
- 重新连接后如果时间戳能够继续严格递增，可以继续使用原会话。
- 如果视频尺寸、摄像头视角或时间基准发生变化，应关闭旧会话并创建新会话。
- 更新插件之前必须先 `stream.close()`，再 `module.close()`，确保后台线程和显存已释放。

### 7.6 多摄像头

每个摄像头创建独立会话，但可以共享同一个 `InstrumentInteractionModule`：

```python
camera_1 = module.create_stream(camera_id="lab_camera_view_1")
camera_2 = module.create_stream(camera_id="lab_camera_view_2")
```

MiniCPM和YOLO模型只保留一份，GPU推理会自动串行，避免多个线程同时操作同一模型。当前只完成了单摄像头实时负载验证；同时运行两个摄像头能否保持足够低的延迟，需要在对方电脑上查看 `analysis_lag_seconds` 和 `dropped_frames` 后确认。

### 7.7 长时间运行的内存策略

- 原始画面只保留最近约4秒。
- 输入队列默认最多300帧，满时丢弃最旧帧以追赶实时画面。
- 姿态记录、VRM原始证据和模型复核记录均有时间或数量上限。
- 对外事件历史默认只保留最近500条，接入方收到事件后应及时写入自己的数据库。
- 不会把24小时原始视频或所有逐帧结果永久放在内存里。

## 八、启动自检

不加载模型的轻量检查：

```python
module = InstrumentInteractionModule(preload_models=False)
print(module.health_check())
```

包含模型已加载检查：

```python
module.load()
check = module.health_check(require_loaded=True)
if not check["ok"]:
    raise RuntimeError(check)
```

检查内容包括 CUDA、MiniCPM 权重、人员检测权重、姿态权重、摄像头配置和模型加载状态。

## 九、可插拔和升级约定

“可插拔”依靠稳定的公共入口与版本号实现：

1. 接入方只导入 `lab_instrument_interaction.InstrumentInteractionModule`。
2. 接入方只依赖本说明中的输入和输出字段。
3. `v4`、`v5`、提示词和融合规则均视为插件内部实现，可以继续优化。
4. 后续更新时，先停止接入方程序并调用旧实例的 `close()`。
5. 将旧模块目录改名备份，再复制新的 `模块` 和必要的 `models`。
6. 检查 `interface_version`：同为 `1.x` 时，现有调用方式应保持兼容。
7. 重新启动后先执行 `health_check(require_loaded=True)`，再用固定回归视频测试。
8. 如果未来接口升级为 `2.0`，接入方应先阅读新版迁移说明，不能直接覆盖。

推荐接入方启动时记录：

```python
print(InstrumentInteractionModule.plugin_info())
```

这样出现问题时可以确认实际运行的是哪个插件版本。

## 十、异常处理

接入方至少应捕获：

```python
try:
    result = module.analyze_video(...)
except FileNotFoundError as exc:
    # 视频、模型或检测权重不存在
    ...
except ValueError as exc:
    # camera_id、时间戳或人员框格式错误
    ...
except RuntimeError as exc:
    # CUDA不可用、显存不足、视频解码或模型推理失败
    ...
```

不要在异常发生后伪造“无交互”结果。应把任务标记为分析失败，否则前端会把系统故障误认为确实没人操作。

流式后台异常不会从后续某一帧重新抛出，而会出现在 `response["error"]` 且 `status="error"`。接入方必须同时检查返回值中的 `error`。

## 十二、当前接口边界

接口 `1.1` 同时提供完整视频分析和非阻塞实时逐帧会话。实时会话已经按真实视频帧率完成单摄像头回归，但仍有以下边界：

- 视角一以及尚未采集真实样本的仪器不能承诺识别准确率。
- 两个摄像头同时运行时的实际吞吐量依赖接入方显卡，尚未在对方电脑验证。
- 流式接口返回结构化状态和事件，不负责保存24小时录像，也不直接控制网页。
- 接入方负责摄像头读取、断线重连、人员身份识别、数据库保存和前端显示。
- 本模块负责短窗口缓存、姿态关系、MiniCPM复核、交互融合和人员—仪器事件输出。
