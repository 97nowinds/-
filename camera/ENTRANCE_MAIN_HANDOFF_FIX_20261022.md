# 入口到主通道身份交接修复（2026-10-22）

## 问题与已确认原因

人脸确认姓名与跨摄全局 ID 关联是两个步骤。入口识别为 yxq，不会自动把姓名交给另一个相机中外观相近的任意轨迹；先要确认两者是同一全局目标。

当前主通道对应 `cam_2`。入口与 Cam2 在门边可以同时观察到同一人。原配置对这一路线启用了 `simultaneous_overlap_validated`，但未配置已有的连续证据确认入口。结果是：

1. 两路同时活跃时，外观分数必须达到 0.75，才会继续参与关联。
2. 例如单人录像 49.9394 秒，源/目标区域条件均通过、ReID 为 0.698291，却返回 `validated_overlap_reid_below_high`。
3. 这类候选甚至进不了后面的连续多次确认流程，主通道于是继续持有自己的匿名全局 ID。

实际运行日志还存在区域外、外观不足和衣服明暗冲突的拒绝。很多记录是不同人的正常拒绝，不能把所有拒绝都算成错误；本次只修复有录像证据支持的主入口重叠门限遗漏。

## 最小修复

`config/floor_map.json` 中 `cam_entrance ↔ cam_2` 的既有路线增加：

```json
"temporal_overlap_min_similarity": 0.68
```

没有修改人体检测器、ReID 权重、ArcFace、几何标定或仪器区域。原有的一次高置信直接关联门限仍为 0.75。

0.68–0.75 的候选改用既有机制：已确认的相机重叠、源/目标进入退出条件、外观与总分门限、候选差距至少 0.08、至少五次观察、持续至少一秒，且相邻证据间隔不超过 0.5 秒。最终合并仍受同相机多目标互斥、不同实名不合并、曾同帧为不同人不合并等限制。它没有按脚点接近直接传递姓名，也没有把地图近似坐标当成身份依据。

该路线原本双向配置，因此连续证据策略也适用于反向重叠观察。其他路线配置未改变。外观低于 0.68 或候选不明确仍保持未知。

## 测试

全部视觉推理位于 lnx GPU0；正式服务测试前未重启。

- 完整回放 base01（32.8 秒）、base04（55.8 秒）、kadun（74.5 秒）、kaoqing（22.6 秒）、单人路线（88.9 秒）。
- 多人长录像只回放 0–180 秒窗口，未跑完约 67.55 小时的整段文件。
- 六组共 17,942 条处理记录，对照原版：原始检测全部相同；局部 ID、检测框、置信度和地图投影测量全部相同。
- 113 项相关测试通过，含五项使用实际路线配置的合成测试：中等分数等待后继承实名、同分候选拒绝、低分拒绝、区域外拒绝、单次观察不确认。
- 结构化对照见 `reports/entrance-main-fix-20261022/comparison.json`。这些统计没有完整逐人真值，不能换算成准确率、IDF1 或零错绑保证。

### 确定性录像关联结果

单人路线增加两次入口到主通道的连续确认：

| 录像时间 | 外观分数 | 累积观察数 | 结果 |
| --- | ---: | ---: | --- |
| 50.9813 秒 | 0.698291 | 27 | 入口身份轨迹与 Cam2 原轨迹关联 |
| 80.7174 秒 | 0.748634 | 26 | 再次重叠时完成连续确认 |

靠近录像 8.8075 秒也有一次确认，分数 0.729213、15 次观察。已查看两路对应画面；该候选与本批其他可评分候选有明显差距。多人的完整身份真值尚未全部标注，因此不称为整体零误合并验收。

base01、base04、kadun 和多人 180 秒窗口未增加此类入口到主通道的确认，不能宣传所有录像都获得提升。

顺序回放本身不运行人脸识别：单人入口首次统一到 `person_1` 从原版 51.1329 秒提前到约 50.9815 秒，仅约 0.15 秒。不能将这一结果夸大成顺序回放提前几十秒。

### 含真实人脸识别的应用流程

另使用真实 `CameraWorker`、SCRFD/ArcFace、原注册图库及录像实时节奏执行隔离回放。第一次对照：

| 首次显示已知身份的回放经过时间 | 原版 | 修复版 |
| --- | ---: | ---: |
| 入口 | 50.90 秒 | 49.87 秒 |
| Cam2 主通道 | 84.79 秒 | 53.42 秒 |
| Cam1 | 66.63 秒 | 66.52 秒 |

修复版该次在入口首次确认后约 3.54 秒，把 yxq 关联到 Cam2；两路显示同一全局 ID。原版入口约 51–57 秒保持 yxq / person_2，而 Cam2 仍为匿名 person_1。

应用采用异步 latest-frame 管线，真实进入关联器的画面及特征采样会随负载变化，不能将单次提前约 31 秒宣称成固定提速。顺序回放与应用回放的采样方式不同，上面两项结果分别记录。应用状态约每 0.5 秒采样，不是精确到帧的人工真值。

为核对异步采样的影响，又在相同集群运行方式下各复测一次原版与修复版：

| 第二轮首次已知身份时间 | 原版 | 修复版 |
| --- | ---: | ---: |
| 入口 | 50.89 秒 | 49.94 秒 |
| Cam2 主通道 | 53.92 秒 | 49.94 秒 |
| Cam1 | 66.53 秒 | 66.59 秒 |

第二轮也观察到主通道更早取得实名，但改善幅度约 4 秒，明显小于第一轮；原版自身也有很大波动。因此结论是这一条路线现在具备更完整的连续确认通道，两次应用试验均更早关联；不是已经证明固定提前 31 秒，也不是整体准确率显著提升的统计结论。第二轮作业状态见 `repeat-jobs.json`。

合计本轮新执行六次检测/跟踪回放、三次含人脸应用回放；对照基线还引用了此前留存的一次原版应用回放。四份应用状态中的三路录像均播放完成，跟踪错误为空。

## 范围与剩余问题

本次修复针对门边同时可见、分数达到连续确认要求的入口—主通道交接。不能保证所有外观变化、遮挡和局部 ID 断裂都已解决。

单人录像末尾约 87 秒的反向入口重现仍可能得到约 0.484 的低外观分，未因本次修复而强制合并。应用回放结束时入口仍可能没有已知身份，不能称为全路线统一身份完成。

回退时只删除本轮新增的路线字段并重启后端；若以后地图标注有更新，不应拿旧地图整体覆盖。
