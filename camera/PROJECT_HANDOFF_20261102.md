## 4. 已实现的人脸补充标定

核心文件：

- `camera/face_adaptation.py`：样本存储、限量、审核、追加。
- `camera/face_adaptation_server.py`：集群 GPU 独立服务。
- `camera/face_adaptation_api.py`：本机代理与访问限制。
- `camera/templates/face_calibration.html`、`camera/static/face_calibration.js`、`.css`：审核页面。
- `camera/scripts/face_adaptation_bridge.py`、`register_face_adaptation_bridge.ps1`：桥接。
- `camera/scripts/capture_recorded_site_faces.py`：录像复用在线方法捕捉。
- `camera/app.py` 中 `/api/face-adaptation/reload`：受保护的图库重载。

用户确认的规则：

1. **清晰度至少 800 才进入审核**，这是拉普拉斯方差分数，不是像素或正确率。10月29日旧报告中的清晰度60是旧值，不能照搬。
2. 人脸最短边64、检测分数至少0.65，并检查亮度/对比度；同一头部 ROI 恰有一张脸才保存。
3. 使用在线相同头部 ROI：人体框横向扩展约0.2w，纵向约 y−0.04h 至 y+0.64h；这不保证裁剪永远正确，仍需人工审核。
4. 24小时采集窗口，每15秒检查；同相机/候选组至少60秒间隔，按姿态和相似度去重；每候选组约20张，每相机上限10张，总保存上限1000张。候选组不等于真实唯一人员。
5. 保存候选小图（最大边512）和内部特征，不持续保存24小时视频。
6. 流程：捕捉 → 待审核 → 用户选择真实注册人员并审核 → 用户确认追加正式图库 → 重载图库。模型建议身份不能自动入库；原注册样本保留。
7. 本机补充标定无需维护令牌，但仅允许 loopback 客户端、loopback Host、同源请求。远端匿名访问仍受限；其他管理接口没有因此取消鉴权。
8. 曾有10项补充标定测试通过；更早16项组合测试通过。历史前端分离回归54/56通过，另两项为已记录跟踪/地图配置断言差异，未修改配置迎合测试。

## 7. 最新待执行方案：口罩与实验服检测

这是最近讨论的重点，**目前只是方案，尚未部署/训练/证明效果**。历史最初想由队友提供 PPE 结果，最新用户提出在本项目增加口罩和实验服检测，建议独立实现并复用已有通知链路。

建议最小结构：

`同帧高清图 + 现有人体框/轨迹 → 头部/躯干裁剪 → 集群 GPU PPE 检测 → 同人多帧确认 → 准备期/分级策略 → 证据快照 → 飞书对应群`

- 不依赖先认出人脸；先判断当前轨迹穿戴，身份可靠时才带真实姓名。
- 口罩初始基线可评估 AIZOO FaceMaskDetection（官方仓库 https://github.com/AIZOOTech/FaceMaskDetection ），必须用本实验室俯拍、小脸、遮挡录像实测。
- 实验服建议轻量检测器或人体裁剪分类器，采集本实验室数据微调；可参考 Ultralytics 官方任务说明 https://docs.ultralytics.com/tasks/ 。普通白衣不能自动当实验服。
- 口罩状态：正确佩戴、明确未戴、不规范、未知；实验服：已穿、明确未穿、未知。未检测到物品不能直接判未佩戴。
- 初始约每人1Hz、裁剪批量推理、只处理最新帧、队列有界、独立服务故障隔离。该频率是设计起点，还没做 GPU 吞吐实测。
- 数据覆盖站立/坐姿/低头/背面/遮挡/普通白衣；按人员或录像时段拆训练验证，禁止相邻帧泄漏。人脸清晰度800不应直接套作躯干检测门槛。
- 先离线评估、不发真实群消息；再接证据/策略和测试通知；通过验收后才启用正式违规规则。

验收：进入后2分钟内穿戴完成不打扰；准备期后持续明确未戴才告警并有正确快照；背脸遮挡保持未知；多人交叉不换人；穿戴恢复正确结束状态；重复事件不重复轰炸；依赖故障不阻塞监控。

统计违规准确率/召回率、未知比例、每人小时误报次数、人员关联错误和端到端延迟；不要只报 mAP，更不能预设准确率。

## 8. 数据绑定与安全边界

- 实时键 `(camera_id, track_id)`；历史回传键 `(camera_id, snapshot_id, track_id)`；global_id是跨摄身份关联，person_id是注册身份，编号语义不能混用。
- snapshot_id 是交接快照，source frame_id 是源帧，不能混淆。
- 图片、bbox、身份和位置必须保留各自来源/时间。缓存旧框不能换上新图片时间冒充同帧；无法同帧需明确容差和风险。
- bbox按照实际图像尺寸转换，不硬编码960/640；高清与辅码流是否同视角要验证裁剪、镜像、旋转、黑边，不能只看宽高比。
- 地图版本与位置应来自同一导出快照；map_id/map_revision 成对约定并等待双方Schema兼容后再启用。
- 地图仪器区域只筛候选，不能直接判断实际操作；交互判断仍由交互模型负责。
- 源时钟曾来自 lnx；不要把主机发送时间冒充采集时间、硬编码时钟差，或把旧位置当新位置。
- 保留Bearer Token、Schema、幂等、白名单、TTL、超时和故障隔离。对外交接不传人脸特征、ReID embedding、凭据和密钥。
