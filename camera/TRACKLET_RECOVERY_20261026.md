# 遮挡后身份恢复：四项修改与验证（2026-10-26）

## 修改范围

修改主项目的关联与身份缓存逻辑。YOLO、ByteTrack、ArcFace、OSNet 权重、摄像头交接区域、地图标定和仪器交互模型不变。原有录像用于集群 GPU 0 上的离线对照，不向飞书发送测试事件。

| 要求 | 实现 |
| --- | --- |
| 短轨迹片段关联 | `tracklet_evidence.py` 保留最近的独立外观观察，容量 12、时间窗口 3 秒。使用近期片段查询长期干净图库，不把较早的各角度图库本身当成当前片段。缓存检测帧不新增投票，重复时间不新增投票。 |
| 遮挡前的干净外观记忆 | `reid_gallery.py` 分开保存 full/upper 特征；遮挡、相互覆盖、明显头部残框不进入身体记忆。边缘截断框不作为完整全身样本。全身代表特征不混入半身向量。图库有容量限制，保留可靠且不同的视角。 |
| 多人竞争与纠错 | 保留一对一 Hungarian 分配、双向候选差距、运动与历史独立人员约束。已有局部 ID 也检查新外观与旧干净记忆的冲突；单次异常先隔离，连续独立异常才撤销绑定。竞争比较只使用已有证据证明不同的人员。 |
| 待确认后恢复原身份 | 一般强候选至少 3 个新鲜外观观察、跨度至少 0.2 秒；中等候选继续使用原先更严格的观察次数和持续时间，已验证重叠交接仍保留其持续时间要求。原 ID、姓名在证据通过前不交给新轨迹。 |

## 关键行为

- `TrackletEvidence` 与长期 `TrackFeatureGallery` 分开。长期图库按质量与视角保留样本，近期片段按真实观测时间收集；同一静止外观的多个真实画面可以提供时间支持，重复使用的缓存帧不能。
- 关联比较按每个查询样本产生一个最佳参考匹配，再做稳健汇总；不再让同一异常裁剪占据多个最高匹配对。
- 对全身和半身只做同类比较；不能因为两个向量维度相同就混用。
- 明显头部残框、边缘截断与身体比例使用几何启发式筛查，不是新增人体部位识别模型。复杂坐姿、遮挡仍可能分类不确定。
- 人体框仍是原检测框。额外 torso ROI 仅用于内部 ReID，不修改地图投影脚点或交接导出的 bbox。
- 多人相似时保留候选、显示未知；不能仅凭脚点相近接管姓名。
- 已绑定局部 ID 出现异常时先冻结外观与运动记忆。单次异常不直接更换全局编号；持续异常达到证据要求后才拆开绑定。
- `app.py` 在绘制和导出之前检查缓存姓名是否仍属于当前全局绑定。不能先画出旧姓名，再在帧末清理。
- `track_diagnostics` 提供 `identity_pending`、`tracklet_evidence`、图库 body_kinds；仅包含计数、状态与真实观察时间，不导出特征向量。

## 启用与回退

配置默认保留兼容路径：`reid.tracklet_recovery_enabled=false`。
运行中的部署可用环境变量 `LAB_TRACKLET_RECOVERY_ENABLED=1` 启用；只允许 `0` 或 `1`，非法值拒绝启动。有效值出现在 `processing.effective_mtmc_config.reid` 与 MTMC 诊断中。

线上部署时给主项目 `lab-safety-api.service` 与独立识别副本 `lab-joint-15002.service` 添加用户 systemd 环境覆盖。8765 的模型、Schema 和数据库不参与这项修改。

回退可把对应覆盖中的开关设为 `0` 后重启识别服务。部署前还应保留源文件备份，以便恢复旧实现。服务重启会建立新的运行期轨迹，不能把重启前后编号连续当成算法效果。

## 测试与解释边界

新增测试覆盖：短时 ID 改变恢复、缓存不计票、候选相同保持未知、距离接近不足以匹配、局部 ID 换人、两个人换号、单帧坏外观、半身恢复、污染样本拒绝、头部残框、边缘截断、证据过期、回放重置、跨摄像头确认和姓名缓存失效。

离线回放使用：

1. `yxq_side_20261009/20261009_134334`，约 89 秒。
2. `multi_person_20261016/20261016_183228` 的前 180 秒。

两版均读取相同的历史检测框、相同的原录像画面，重新在 GPU 上计算 ReID。多日录像的检测缓存并非完整可读文件，本轮只使用已确认可读的前 180 秒，未声称覆盖全部多日录像。

检测、跟踪和人脸识别没有在这组对照中重新运行，因此不能用它衡量检测召回、人脸识别成功率或完整实时负载。录像没有逐帧人工身份真值；全局编号数量、编号变化次数和合并次数不能直接解释为 IDF1、错绑率或正确率。

人工抽查发现过两类误触发：正常转身后外观变弱，以及最初仅有头部残框随后露出身体。实现据此增加了异常隔离与残框分类，而不是把“编号越少”当作成功。

最终回放摘要、部署文件校验及线上可用性检查保存在本机 `runtime/tracklet-recovery-20261026/`。这些记录不包含 ReID embedding 或人脸特征。

## 2026-10-27 最终验收状态：候选版，未上线

代码已实现；145 项针对性与兼容性测试通过，其中新增 27 项片段恢复测试。单人录像处理 3327 个新鲜检测批次，多人前 180 秒处理 6982 个批次，均在 GPU 0 重新计算外观特征。

| 指标 | 原版 | 最终候选版 |
| --- | ---: | ---: |
| 单人样本分配的全局编号数 | 13 | 13 |
| 单人样本同一局部编号的绑定变化次数 | 8 | 2 |
| 多人样本分配的全局编号数 | 35 | 36 |
| 多人样本同一局部编号的绑定变化次数 | 23 | 23 |
| 单人关联耗时 P95 | 11.49 ms | 13.08 ms |
| 多人关联耗时 P95 | 12.32 ms | 14.37 ms |

以上“绑定变化”同时包含正确恢复、错误切换与合并重定向，减少该数值不能证明正确率提高；编号分配数包括临时待确认编号。

**未通过完整路线统一身份验收。** 单人片段仍未完成所需的跨摄像头多帧确认，多人样本仍有额外分裂。新鲜证据的部位一致性、观察时间、单对候选差距和路线限制共同影响能否通过；不能为了合并编号就调低所有阈值，或者把缓存帧当作新的支持证据。

因此本轮仅交付候选源码、测试和回放结果。没有运行部署脚本，没有重启线上识别服务，没有启用新开关。最后检查 15001 与 15002 的三路摄像头均为 running，`tracklet_recovery_enabled` 仍为 false。

后续应先为录像中的关键交接窗口建立匿名人员 A/B 真值，分别检验漏关联与误关联，再调整片段评分/可见部位策略。当前结果不能宣称已经改善多人真实错绑率或达到全程统一身份。
