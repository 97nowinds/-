# 穿戴准备期与通知责任分工

日期：2026-10-19。用户确认：没有固定准备区；entrance 首次确认人员身份时开始计算，穿实验服/戴口罩准备期为 2 分钟。

## 接收群含义

| 系统路由 | 实际接收人 | 应处理的情况 |
| --- | --- | --- |
| experimenters | 正常学生、实验人员 | 普通防护提醒，先自行整改 |
| managers | 负责的师兄师姐 | 学生持续未整改，组织核查和处理 |
| administrators | 负责的老师 | 火焰等严重安全事件，本轮不因普通穿戴超时直接通知老师 |

这些是群接收责任，不是另建个人网站账号，也不根据识别姓名猜测谁是老师或师兄师姐。保留原三个 Webhook 和路由 ID，新增中文含义。

## 事件应如何传递

1. entrance 的新鲜、已锁定人脸身份启动该注册人员的 120 秒准备窗口。不依赖地图准备区；不能把 entrance 的整个视野当成安全区域。
2. 普通进入只留档。窗口内的未穿戴样本不累计成防护违规，不能在窗口结束时把旧的准备画面拿出来发送。
3. 120 秒到期不会自动报警。必须重新取得不同源帧、跨度至少 5 秒且置信度满足规则的新鲜未穿戴证据。首次确认 L1 后，使用该次实际快照发学生群。
4. 首次 L1 提醒事件生成后，继续有效确认未整改达到 60 秒，才生成 L2，发学生群和负责师兄师姐群。这个计时不是从收到飞书的回执或人工阅读时刻开始；外部网络的送达延迟独立记录。
5. unknown、遮挡、低分或观测间隔超过上限中断持续违规累计；不能把未知间隔算成持续违规，也不能当成已整改。
6. 有效的 worn 观测登记恢复，停止升级，并取消尚未领取投递的旧违规消息。已开始的网络请求或已经发出的消息无法保证撤回。当前恢复按现有有效检测结果处理，是否需要多帧整改确认可后续单独配置验证。
7. 如果队友通过严格原快照键、权威时间和有效 true 结果确认开始操作指定仪器，可提前结束准备期。地图候选、false、pending、旧结果不能结束准备期；结束准备期本身也不制造违规，仍须真实 PPE 证据。
8. 火焰是环境事件，直接走 L3 三群通知，不等待人脸、准备期或 PPE 累计。视觉模型当前仍在 experimental_observe，本轮不赋予其正式告警资格。

| 合成场景 | 应出现的事件/投递 |

## 实现

- `ppe_preparation.py`：持久化窗口，按 person_id 关联，不按 local ID 或 global ID 建新窗口。
- `EvidenceAdapter.cameras`：只对新鲜、已锁定的 entrance 人脸身份触发；录像回放不触发。
- `EvidenceAdapter.analysis`：严格验证的仪器 true 结果可结束窗口。
- `PPEPolicy.observe`：准备期样本不进入违规累计，升级计时在首次有效提醒后开始，未知/间断中断累计。
- `SafetyIncidents.recover_ppe`：取消未开始投递的旧防护消息。
- `config/management.json`：准备期 120 秒，三群中文责任含义；口罩开启，实验服/手套仍等检测侧接入后启用。
- 维护页/只读状态接口显示准备期和实际群含义。

## 已知边界：再次进出

入口相机看见或认出某人，不足以证明这人正在进入还是正在离开。现有入口记录也不能保证每次进出方向准确。因此本轮采用保守策略：同一注册人员的窗口持久化，不因跟踪丢失、重新露脸、等待一段时间或重启而自动重开。

`close_visit` 已预留给独立确认的离场或维护纠正，但当前没有自动离场事件调用它。**新一轮真实离场后再入场的自动重置尚未完成**，需要后续接入可信的进出事件，并在单门双向通行录像中验证。不能把这项描述为已完整实现的多次入场准备期。

准备窗口初始时间使用主机首次接收到新鲜身份确认的时刻，不伪装成源帧采集时刻。违规消息继续保留原图像/检测时间。迟到的入场确认不能用来重开已有违规的准备期。
